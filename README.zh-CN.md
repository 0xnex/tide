# BTC 50 日均线基金（Solana devnet 原型）

任何人都可以用 USDC 申购份额。每天 UTC 1 点之后结算一次：BTC 价格高于 50 日均线就持有 BTC，否则持有 USDC。申购和赎回都先排队，统一按结算时的净值成交。

> **这是测试网原型，不能直接上主网接受别人的资金。** 价格来自管理员手动设置的模拟预言机，兑换走模拟交易所。上主网前需要替换成真实的预言机和交易所，完成安全审计，并咨询律师（向他人募集资金统一投资，在很多地区需要牌照；在中国大陆还可能涉及非法集资）。

## 目录结构

```
tide/
├── fund-logic/            所有记账逻辑（纯 Rust，无依赖），含 18 个单元测试
├── programs/tide/         Anchor 合约：账户校验、代币转账，调用 fund-logic
├── tests/tide.ts          端到端测试（bankrun，可快进时间模拟多天结算）
├── scripts/crank.ts       每日结算脚本（devnet 用）
├── Anchor.toml / Cargo.toml / package.json / tsconfig.json
```

## 工作流程

| 时间 | 发生什么 |
|---|---|
| UTC 1 点之前，或当天结算之后 | 用户 `request_deposit`（存入 USDC）或 `request_withdraw`（交回份额），进入本期排队 |
| 每天 UTC 1 点之后 | 任何人调用 `settle`：记录 1 点发布的价格 → 计算 50 日均线 → 按净值处理本期申购赎回 → 高于均线全部持有 BTC，否则全部 USDC |
| 结算之后 | 用户 `claim` 领取份额或 USDC |

关键设计：

- **申购也按下一次结算的净值成交**，防止有人在 BTC 大涨后用旧净值买入，稀释其他人。
- **固定定价时刻**：净值和买卖信号用 UTC 1 点后 60 秒内发布的预言机价格，和调用 `settle` 的时间无关，调用人无法挑选对自己有利的时刻。兑换数量按最新价格计算，最新价格与 1 点价格最多相差 1%，超过则当天结算回滚、跳过。
- **定价时刻之后暂停排队**：1 点价格已经公开，所以从 1 点到当天结算完成，申购赎回请求会被拒绝；结算后立即重新开放（进入下一期），如果当天没人结算，第二天 0 点重新开放。
- **内部记账**：净值按合约记录的资产计算，不读代币账户余额，别人直接转钱进来无法操纵净值。
- **领取精确分配**：每期最后一位领取的人拿走取整余数，所有人领取之和精确等于本期总额，不留“尘埃份额”。（早期版本里尘埃份额会在所有人赎回后让基金永久卡住，测试发现后已修复。）
- **滑点保护**：兑换成交少于预言机价格的 99.7%（可配置；Binance 手续费 0.075% + 滑点约 0.1%，再留出预言机与交易所的价差）时，整笔结算回滚。
- **所有人都赎回也不会卡住**：如果为了付赎回款卖 BTC 产生的成本让 USDC 略少于应付金额，差额由本期赎回人按比例承担。
- 可选的申购费、赎回费（默认 0）：留在基金里，补偿其他持有人为申购赎回承担的交易成本。

## 运行

需要：Rust、Solana CLI 2.x、Anchor 0.31.1（建议用 avm 安装）、Node 20+、yarn。

```bash
# 1) 纯逻辑测试，不需要 Solana 工具链
cd fund-logic && cargo test && cd ..

# 2) 生成程序地址并写入代码
anchor keys sync

# 3) 编译合约
anchor build

# 4) 端到端测试
yarn install
anchor test
```

> 合约部分我无法在编写环境里编译（那里访问不了 Rust 包仓库和 Solana 工具链），所以第 3、4 步是第一次真正编译。如果报错，把完整错误信息发给我修。`fund-logic` 的测试已经全部通过。

## 部署到 devnet

```bash
solana config set --url devnet
solana airdrop 2
anchor deploy --provider.cluster devnet
```

然后按 `tests/tide.ts` 里 `before()` 的顺序初始化：创建模拟 USDC（6 位）和 BTC（8 位）代币 → `init_mock_oracle` → `init_mock_market` 并注入流动性 → `initialize` → `init_vaults` → `seed_prices`（写入最近 49 天的历史收盘价）。

每天 UTC 01:00 运行一次结算脚本（cron 示例，服务器时区为 UTC；模拟预言机的价格必须在 1 点后 60 秒内写入）：

```
0 1 * * * cd /path/to/tide && ANCHOR_PROVIDER_URL=https://api.devnet.solana.com ANCHOR_WALLET=$HOME/.config/solana/id.json yarn ts-node scripts/crank.ts >> crank.log 2>&1
```

## 配置项

| 参数 | 默认 | 含义 |
|---|---|---|
| window | 50 | 均线天数（最多 64） |
| settle_offset_secs | 3600 | UTC 0 点之后多少秒可以结算 |
| max_slippage_bps | 30 | 兑换相对预言机价格最多允许 0.3% 的损失 |
| deposit_fee_bps / withdraw_fee_bps | 0 | 申购费 / 赎回费，留在基金里 |
| min_deposit | 1 USDC | 最低申购 |
| max_staleness_secs | 600 | 预言机价格最多允许多旧 |

## 已知局限和下一步

1. **预言机**：改用 Pyth BTC/USD，检查置信区间和更新时间。
2. **兑换**：改用 Jupiter。路由在链下计算，合约里用预言机价格校验最低成交量。
3. **执行方式**：资金规模变大后，把一次性买卖改成分批执行（见下）。
4. **撤单**：目前排队后不能撤回，可以加 `cancel_request`。
5. **管理功能**：暂停开关、多签管理员、参数修改的时间锁。
6. **漏结算**：如果某天没人调用 `settle`，那天的价格会缺失，均线按“观测到的最近 50 个价格”计算。上线后需要可靠的定时任务和监控。
7. **安全审计和法律咨询**：接受任何外部资金之前必须完成。

## 买卖执行：怎样做得更好

每天固定时间、按公开规则在链上买卖，会遇到三个问题：别人能预判并夹单、大额交易冲击价格、交易所价格偏离预言机。改进方法从简单到复杂：

| 方法 | 作用 | 状态 |
|---|---|---|
| 用预言机价格设最低成交量 | 防止被夹单或成交价太差 | 已实现（默认 0.3%） |
| 申购费、赎回费 | 让产生交易的人自己承担成本 | 已实现（默认 0） |
| 分批执行（TWAP） | 一次大单拆成多笔，在一段时间内完成，降低冲击和被预判的损失 | 资金变大后再做 |
| 执行时间随机化 | 在 1 点到 2 点之间随机挑时间，更难预判 | 可选 |
| 走防夹单通道 | 通过 Jito 等私有通道发送交易 | 主网时考虑 |
| 限价单 | 用 Jupiter 限价单代替市价成交 | 主网时考虑 |

资金只有几千美元时，前两项已经够用；分批执行等到单笔交易规模明显影响价格时再加。
